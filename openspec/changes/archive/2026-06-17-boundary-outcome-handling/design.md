## Context

This change resolves RFC App. **D.34** and elevates the governing principle to RFC **§1.2.1** — surfaced by the Phase-6 greenfield POC, the **4th instance** of the D.26→D.33 lesson. It is the **extraction** of that lesson into a principle rather than a fourth one-off patch (Rule of Three).

**The governing principle (the user's north star — non-negotiable).** Dusk must not couple to any specific tech's nuances. The **deterministic core** may act **only** on signals it **itself authored** (intent syntax, intent files, the decoration grammar, the orchestration flow) or that are **universal across every stack** (its own timeout firing; whether returned bytes parse into Dusk's own schema). Anything requiring **judgment about what a specific tool's output means** — the *project's tech surface* — **must be interpreted by agentic AI**, never hard-coded into the core. The core orchestrates across any stack; **agentic AI is the bridge**.

**The verified diagnosis (board + preserved traces).** A Phase-6 POC build looped ~21× re-drafting correct code and paused. The board verified the live code and the preserved traces (`dusk-notifications-poc/.ia/observability/traces.jsonl`):

## The conceptual model + the universal three-way outcome

The core (a) runs a project-/intent-defined command, (b) owns the clock + the kill, (c) checks whether returned bytes **parse into Dusk's own schema**, and (d) routes control flow only on **Dusk-authored verdicts**. The bridge is the only thing allowed to hold an opinion about a tool; the core is the only thing allowed to drive control flow. Every boundary crossing resolves to **exactly one**:

- **`content`** — Dusk-schema-valid AND content-complete. The **only** outcome that may drive re-draft / commit.
- **`no_verdict` (infrastructure)** — empty / unparseable / incomplete / deterministic-limit / tool-infrastructure. A distinct recovery axis: **never** a content fail, **never** a silent green, **never** a crash, **never** burns content-iteration budget.
- **`transport`** — call-plumbing (spawn/pipe/our-own-timeout). Retried **once**; second death → `no_verdict`. Deterministic-limit failures are never cold-retried.

**Core MAY act on** (liveness only): Dusk's own timeout firing; whether bytes parse into Dusk's own schema. **Core MUST NOT act on**: exit code as verdict (137 OOM ≠ 1 assertion ≠ 0-with-zero-tests ≠ 127 missing-binary); "output produced" as success; a tool's status vocabulary; a parseable verdict treated *as content* (schema-valid ≠ correct).

## Signal-reliability verdict (the board's answer to the user's doubt)

Only two candidate "universal" signals are genuinely stack-invariant — and only as **liveness/transport** facts, never as content:

| Signal | Verdict | Why |
|---|---|---|
| Dusk's own timeout fired | ✅ trustworthy (liveness) | Dusk owns the clock + the kill. |
| Bytes parsed into Dusk's OWN schema | ✅ trustworthy (liveness) | Decided against Dusk's own Zod shapes. NOT a content signal. |
| Exit code | ❌ lies | 137/1/0-zero-tests/127 arrive identically; `pnpm` passthrough. |
| "Output produced at all" | ❌ lies | A 0-token response *is* transport-layer output; SIGKILL truncation. |

Deepest finding: **"parseable verdict" is reliable liveness but unreliable content** — a model can return schema-valid-but-wrong or parseable-but-degraded JSON. So there is **no purely-mechanical, purely-universal *content* signal** — which is exactly why content interpretation stays agentic while a mechanical floor preserves the honesty duals.

## Goals / Non-Goals

**Goals:** one classifier vocabulary + one three-way outcome in the `core/schema` leaf; require positive success evidence everywhere (no verdict from silence); a mechanical floor for Stage-2 that does not re-couple to a toolchain (the project-side adapter / Dusk-result-schema); stop the silent green and the downgrade; guard every opaque-output boundary against a crash; a finite, resumable infrastructure-recovery axis; both honesty duals model-independent.

**Non-Goals:** reshaping verification logic; a new package; a `BoundaryOutcome<T>` generic; a 6-value `NoVerdictReason` *as error kinds* (it is a `detail` on one kind); `confidence`/`abstain` self-report fields (no consumer); a separate budget *system* (reuse pause/precedence + one counter); building the project-side adapter (Phase VI); touching the POC repo; bringing `git` exec into scope.

## Requirements (normative — R1–R11)

- **R1** Core branches only on (a) its own timeout and (b) parse-into-Dusk-schema. No branching on a toolchain value's meaning.
- **R2** Every boundary resolves to exactly one of `{content | no_verdict | transport}` via **one** classifier vocabulary (no per-package re-implementation). The classifier is a **gate** every boundary routes through.
- **R3** That classifier + outcome type live in the `core/schema` leaf (one source of truth; extends `modelCallError.ts`).
- **R4** No tool name, flag, or status vocabulary in the core. A tool-specific result *shape* may be read only if it is **Dusk's own schema**, populated by a project-side adapter (decision ①).
- **R5** Mapping opaque runner output → a `TestVerdict` is done by the agentic bridge OR by reading Dusk's own result schema; the core supplies only `{command, exitCode, stdout, stderr, timedOut}`.
- **R6 (dual A)** A `no_verdict` MUST NOT be presented as a content fail and MUST NOT consume content-iteration budget. *(Kills the ~21-iter loop.)*
- **R7 (dual B)** A content-complete `fail` MUST drive re-draft; a content-complete Stage-2 `decision:"fail"` MUST block commit. The core MUST NOT report green on anything that is not a content `pass`. *(Kills the silent-green.)*
- **R7a (dual C)** A `no_verdict` pause MUST be **resumable and legible** (a real resume seam), never a silent stall.
- **R8** No control-flow decision derived from the *absence* of a negative signal. Missing/degraded units are detected by a **positive completeness check** → `no_verdict`. No `?? false` / `?? "vague"` / `status!=="passed" ⇒ fail` defaults.
- **R9** No non-content outcome may terminate the process via an uncaught throw. Every opaque-output boundary is guarded.
- **R10** `no_verdict` surfaces on a recovery axis with a **finite** retry counter and a terminal legible pause; never a terminal `recoverable:false` downgraded at a downstream site.
- **R11** Both honesty duals hold **model-independently** — the mechanical guards alone prevent silent-green and false-loop regardless of model behavior.

## Decisions

### D1 — One classifier + one three-way union in the `core/schema` leaf; right-sized (decision ②; R2/R3)

A flat `BoundaryOutcome` discriminated union — `{kind:"content"} | {kind:"no_verdict", reason} | {kind:"transport"}` — and one `classifyBoundary(...)` gate, in a new `core/schema/src/boundaryOutcome.ts` (pure; imports only `zod` siblings — `core/schema` imports nothing internal, so no cycle). **`BoundaryOutcome` is a TS type, NOT a Zod schema** — it is internal control flow, never serialized; only the persisted pieces are Zod: `NoVerdictReason` (rides in `DuskError.details`), the new error kind `infrastructure_no_verdict`, and the new bead status `paused_infrastructure`. The classifier takes already-derived facts (`{threw, error, parsedToDuskSchema, completenessHeld, timedOut}`) — **never a raw exit code as a branchable field** (R1/R4). *Cut* (decision ②): the generic `BoundaryOutcome<T>`; a 6-value `NoVerdictReason` as error kinds; `confidence`/`abstain` self-report fields; a separate budget system. Lift `withTransportRetry`/`TransportLegFailure` into `core/schema` (they depend only on `isTransportError`, already there) so transport-retry is reachable on the runtime path **without** a `benchmark`/`test-harness` edge — resolving "transport-retry lives only in benchmark" at the root.

### D2 — Require positive success evidence in BOTH verifier procedures (the live trigger; R8)

Both verifier procedures SHALL replace their `?? false` / `?? "vague"` defaults with a **positive completeness predicate** at **both** levels: every triple in scope MUST have a matching answer entry, and every support id MUST have a matching entry. The two sites: `verifyIntent` ([procedure.ts:120-154](../../../packages/runtime/verifier/src/procedure.ts#L120-L154), `answer?.affirmative_holds ?? false` / `?? "vague"`) on the semantic/short-cycle path, **and** `realTestPrepassVerdict` ([testPrepass.ts:87](../../../packages/runtime/benchmark/src/testPrepass.ts#L87), `answer?.genuinely_verifies ?? false`) on the live Stage-1 **test-intent pre-pass** — the latter is the boundary the looping **test** bead `bd_…005` routed through (`isTestIntentPath ⇒ route "prepass"`, [implement.ts:301,395-397](../../../packages/cli/src/implement.ts#L395-L397)), so it is on the live trigger path, not an aside. Any missing/degraded unit ⇒ return `no_verdict` (incomplete), never a fabricated `fail`. This **subsumes the parseable-empty `{triples:[]}` degenerate** (the confirmed live trigger): a degraded response not covering the scoped triples is `no_verdict`, never a false-converge. (`realTestPrepassVerdict` lives in `@dusk/runtime-benchmark` only because that is where the real-model pre-pass currently lives; the fix is identical regardless of package.) The **bridge's own parse is itself guarded** — a non-parseable/empty bridge response resolves to `no_verdict`, never silently to `fail` (which would manufacture a re-draft on infra noise) and never to `pass`.

### D3 — A mechanical floor that does not re-couple to a toolchain (decision ①; the crux; R4/R5/R11)

A *pure-agentic* Stage-2 makes a stochastic model the sole gate against shipping broken code and makes R7/R11 untestable — so a mechanical floor is required. To avoid re-introducing tech-coupling, **mirror the decoration model**: the project's *test command* emits results in **Dusk's own result schema** via a thin **project-side adapter/reporter** (a vitest reporter, a pytest plugin — the project's tech surface, configured in the foundation intent). The **core reads only Dusk's own schema** (`failed>0 ⇒ content fail`; `passed>0 ∧ failed==0 ∧ completed ⇒ pass`; `not_run` ≠ fail) — mechanical, fully regression-testable, zero tech-coupling. The schema carries an explicit **`completed` (ran-to-completion) assertion** + per-state counts; the floor cross-checks Dusk's own liveness facts: a schema-present `failed:0` with `completed:false` (OOM/SIGKILL-truncated, or Dusk's timeout fired) ⇒ `no_verdict`, **never `pass`** (the Stage-2 analogue of "parseable-but-degraded" — the masking risk the AI lens caught). The **agent interprets only when Dusk's schema is absent** (reporter crashed / OOM / timeout / garbage) → `no_verdict`, or `fail` where it reads a genuine assertion failure in raw output. **The agent can never downgrade a Dusk-schema assertion failure to a flake, and never manufacture a green** — the asymmetry guaranteeing R7. The project-side adapter is a **Phase-VI / project-side task**, NOT part of this dusk change.

### D4 — Stop the silent green by consuming the Stage-2 `decision`, wired into the existing livelock block (gap #1; R7)

The orchestrator's Stage-2 path ([stateMachine.ts:331-349](../../../packages/runtime/orchestrator/src/stateMachine.ts#L331-L349)) pushes the test intent as "executed" **without reading `TestVerdict.decision`** → broken code ships green. Tested nowhere today. The fix lives in the **Test Runner**, not the orchestrator: `run.ts` classifies a content `decision:"fail"` as a `reenter_step4` outcome (the existing kind), so the orchestrator routes it through the **existing** livelock-observation block ([stateMachine.ts:334-347](../../../packages/runtime/orchestrator/src/stateMachine.ts#L334-L347)) — re-draft + blocked commit, with **zero new orchestrator branches** (no new unbounded loop). A `no_verdict` becomes a **new third `TestRunnerOutcome` kind** routed to the infra axis (NOT to `livelockObservations`). *Rejected:* re-deriving the decision in the orchestrator (duplicates classification away from the runner that holds the verdict).

### D5 — Stop the downgrade with a new `no_verdict` outcome kind, not a flag flip (gaps #2/#9/#6; R10)

The three sites that mint `recoverable:false` from an empty/degraded verdict ([loop.ts:172](../../../packages/runtime/short-cycle/src/loop.ts#L172), [run.ts:77](../../../packages/runtime/test-runner/src/run.ts#L77), [longCycle.ts:36](../../../packages/runtime/long-cycle/src/longCycle.ts#L36)) route empty/degraded → `infrastructure_no_verdict`. **Critically, nothing downstream consumes `recoverable` on these return paths** (`processBead` propagates `!short.success` straight out of `runImplement` — [stateMachine.ts:264](../../../packages/runtime/orchestrator/src/stateMachine.ts#L264)), so a flag flip alone leaves the loop fatal-on-infra. The fix adds a **new `no_verdict` outcome kind** to `ShortCycleOutcome` and `TestRunnerOutcome` (peers to `budget_exhausted`/`escalated_iter15`), which `processBead` routes to the infra axis exactly as `budget_exhausted` routes to the recovery ladder.

### D6 — Guard every opaque-output boundary against a crash (gap #3; R9)

`execFileSync` → `spawnSync` in `vitest.ts` ([:18-19](../../../packages/runtime/test-runner/src/vitest.ts#L18-L19)) and the CLI runner ([implement.ts:434-444](../../../packages/cli/src/implement.ts#L434-L444)) — a non-zero exit is **data**, never a throw; capture `{command, exitCode, stdout, stderr, timedOut}`. Every `JSON.parse` over opaque output is guarded → `no_verdict` on failure. A **defensive `catch`** is added to the orchestrator's `try…finally` ([stateMachine.ts:144,213](../../../packages/runtime/orchestrator/src/stateMachine.ts#L144)) so any sync throw in `processBead` surfaces a legible DuskError, never `exit 1` — **narrow in spirit** (it surfaces, it does not relabel a programming bug as a content outcome; a `TypeError` is surfaced as `internal_error` and is loud, never `no_verdict`).

### D7 — A finite infrastructure-recovery axis (the new holes; R10/R7a)

`precedence.ts` ([:16-23](../../../packages/runtime/livelock-detection/src/precedence.ts#L16-L23)) gains a `no_verdict` arm — order **`livelock > no_verdict > budget`** (it sits between the two existing checks). It **stays a pure detector**: the finite counter lives in `processBead`'s closure (like `testReentryCount`/`lifetimeIter`) and `noVerdictExhausted` is passed in as a third plain input. `no_verdict` iterations are **excluded from livelock reject-observations at the push site** — only a *content* reject becomes an observation; consecutiveness is over the **content-observation sequence** (an interleaved infra blip is transparent — it neither fills nor resets the 3-reject window, so a real livelock still trips). A terminal counter exhaustion sets `paused_infrastructure` and writes the **same L3 freeze resume record**, so `dusk implement --resume bd_…` re-enters `processBead` from the frozen iteration ([resumeFrozenBead](../../../packages/runtime/orchestrator/src/stateMachine.ts#L401); CLI `bd_` dispatch [implement.ts:465](../../../packages/cli/src/implement.ts#L465)); `paused_infrastructure` is added to `BEAD_STATUSES` ([activeRun.ts:14-25](../../../packages/runtime/orchestrator/src/activeRun.ts#L14-L25)) and the CLI `IN_FLIGHT` set. **No new resolve verb** — reuse the freeze/`bd_` path (simpler, already wired).

### D8 — Long-cycle confirmation stays honest (R7)

A `no_verdict` confirmation spawn in the long cycle ([longCycle.ts:62-102](../../../packages/runtime/long-cycle/src/longCycle.ts#L62-L102)) is **neither a confirming reject nor a flaky-dismiss**: `confirmingRejects` is computed over *parsed* verdicts only, and a `no_verdict` confirmation routes the **bead** to the infra axis (pause) rather than letting `confirmingRejects` fall to 0 and dismiss the original reject as flaky. The GOOD N=2 flaky-dismiss pattern is otherwise preserved. Forbidden (a test): original `reject` + two `no_verdict` confirmations ⇒ MUST NOT emit clean/dismiss.

### D9 — One vocabulary, not two; gap #7 demoted (R2)

The two ad-hoc retry checks in the CLI ([implement.ts:421,428](../../../packages/cli/src/implement.ts#L421-L428)) re-classify `verifier_model_call_failed` outside the core classifier — a second vocabulary that would diverge when `infrastructure_no_verdict` lands. They are folded into the single classifier. The existing dead kind `test_runner_command_failed` is documented as **superseded** by `infrastructure_no_verdict` for the Stage-2 boundary. **Gap #7** ([modelClient.ts:178](../../../packages/runtime/verifier/src/modelClient.ts#L178) unguarded success-path `JSON.parse`) is **already mitigated** — a `SyntaxError` is caught at the spawn seam and classified transport via `modelCallError.ts:42` — so it lands as a **guard regression test** asserting that mitigation holds, not a new fix. Honest count: **eight fixes + one guard-test**, under the nine-gap lineage framing.

### D10 — `git` exec out of scope, deliberately

`git` `execFileSync` in `commit.ts`/`merge.ts`/`worktree.ts` is a **universal orchestration signal** — git exit codes are stable, and git is Dusk's **own** orchestration substrate (Dusk creates the worktrees, makes the commits, runs the merges), not the project's tech surface. It is kept outside the boundary-outcome union — an intentional, stated asymmetry, not an oversight.

## Determinism & honesty posture

**Zero-model, regression-testable (holds both duals regardless of model):** the positive completeness check; parse-into-Dusk-schema; the Dusk-result-schema floor (`failed>0 ⇒ fail`, `completed:false ⇒ no_verdict`); the transport/limit classifier; the routing tables; the finite counters; consuming `decision`. **Agentic (judgment, tech surface):** flake-vs-failure *only* on output that did not yield Dusk's result schema. The asymmetry guaranteeing R7: the agent can only push toward `no_verdict`/`fail` — never downgrade a Dusk-schema assertion failure, never manufacture a green. The one residual where model behavior still leaks (acceptable, out of scope): a schema-complete, schema-valid, but **factually wrong** verdict — §5 concedes there is no mechanical content signal; the duals hold against *silence/degradation*, not against confident wrongness, and the design says so honestly.

## Risks / Trade-offs

- **[Trade a silent-green for a new unbounded loop]** — the gravest gap-#1 failure mode. **Mitigation:** D4 routes the content `fail` through the **existing** livelock-observation block (no fresh loop); the re-audit greps that gap #1's re-entry is wired there.
- **[The classifier becomes a vocabulary, not a gate]** — nine sites with a remembered convention is one `??` from a tenth gap. **Mitigation:** R2 as a gate; the re-audit greps that no `?? false` / `?? "vague"` / `anyPass && !anyFail` survives anywhere.
- **[Adapter masks an OOM as `failed:0`]** — a partial/streamed result file SIGKILLed mid-run. **Mitigation:** D3's `completed` ran-to-completion assertion + the liveness cross-check ⇒ `no_verdict`, never `pass`.
- **[Infra noise hides a real livelock]** — excluding `no_verdict` from observations could mask a genuine livelock. **Mitigation:** D7 makes consecutiveness over the *content*-observation sequence (infra iters transparent, not window-filling/resetting).
- **[Over-broad catch swallows a bug]** — D6's defensive `catch`. **Mitigation:** it surfaces a `TypeError` as a loud `internal_error`, never relabels it `no_verdict`/content (mirrors D.33's narrow-catch honesty bar).
- **[Pile-on]** — Fowler's anti-pile-on. **Mitigation:** one principle (positive evidence), one classifier gate, one new error kind, one new status, one finite counter; gap #7 demoted; the generic union / self-report fields / separate budget system all cut.

## Migration Plan

Additive + corrective within the dusk monorepo; no data migration. Sequence (`^build`): `core/schema` (union + classifier + `infrastructure_no_verdict` + `paused_infrastructure` + the Dusk result schema + lift `withTransportRetry`) → `verifier` (completeness check, guard) + `test-runner` (`spawnSync` capture, Dusk-schema reader, `decision`→`reenter_step4`, `no_verdict` kind) → `short-cycle`/`long-cycle` (`no_verdict` kind, stop downgrade, honest confirmation) → `orchestrator` (consume `decision`, infra axis + finite counter + `paused_infrastructure` + resume + defensive catch) → `cli` (`spawnSync` runner, fold retries into the classifier, accept `paused_infrastructure`). The D.32 no-marker guard and D.33 spawn seam are untouched. Lands **before the Phase-6 POC resumes** (the build is paused pending it); the project-side adapter is handed back as a Phase-VI task.
