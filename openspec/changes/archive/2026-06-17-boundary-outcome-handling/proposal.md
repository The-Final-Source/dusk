## Why

A Phase-6 POC build looped a bead **~21 short-cycle entries re-drafting correct code** and paused. The original diagnosis (a "Stage-2 Vitest worker-pool flake") was **wrong and is superseded**. A four-lens arch board verified the live code + the preserved POC traces (`.ia/observability/traces.jsonl`, 114 rows) and established the real mechanism:

The short-cycle **Verifier returned empty/0-token responses under extreme concurrent load** — **30 of 34** Verifier calls were 0-prompt + 0-completion tokens at **25–74 s** on `claude-sonnet-4-6` (the box was massively oversubscribed; Engineer legs of 800 s+). **The test runner was never reached** (zero `test-execution` traces). The **confirmed live trigger** (bead `bd_…005`, the 75-trace looper — a **test bead**) was the degraded response **silently coerced into a definite, falsely-converging verdict**: the verifier procedures build per-triple verdicts with `answer?.affirmative_holds ?? false` and `answer?.supports.find(...)?.triple_verdict ?? "vague"` ([procedure.ts:124,133](../../../packages/runtime/verifier/src/procedure.ts#L124-L133) on the semantic path; the identical `answer?.genuinely_verifies ?? false` at [testPrepass.ts:87](../../../packages/runtime/benchmark/src/testPrepass.ts#L87) on the live Stage-1 **test-intent pre-pass** the looping test bead actually routed through — `realTestPrepassVerdict`, wired at [implement.ts:395-397](../../../packages/cli/src/implement.ts#L395-L397)), so a degraded/missing model answer defaults to a concrete focal verdict. The verdict then slipped through the short-cycle's `!verdict || isDuskError(verdict)` guard ([loop.ts:171](../../../packages/runtime/short-cycle/src/loop.ts#L171)) as valid **content** and converged on an empty failing set ([loop.ts:178](../../../packages/runtime/short-cycle/src/loop.ts#L178)) — the bead advanced, re-entered from a downstream step, and re-converged falsely again, endlessly. The twin path the original diagnosis named — `parseModelResponse → null → recoverable:true` **downgraded to `recoverable:false`** at [loop.ts:172](../../../packages/runtime/short-cycle/src/loop.ts#L172) / [run.ts:77](../../../packages/runtime/test-runner/src/run.ts#L77) / [longCycle.ts:36](../../../packages/runtime/long-cycle/src/longCycle.ts#L36) — is a **real but latent** defect of the same family.

The single root pattern across all of it (Fowler): **"inferring verdict from silence"** — reading a control-flow decision off the *absence* of a negative signal (`anyPass && !anyFail`, `?? false`, `status!=="passed" ⇒ fail`, an empty verdict read as a clean accept). This is the **4th instance** of the D.26→D.33 lesson (a non-deterministic / infrastructure failure mistreated as a genuine/retryable content failure → futile loop or crash). By the Rule of Three the principle is **extracted, not patched a fourth time**.

This change resolves the gap from first principles, ratified by a four-lens arch board (architect, backend, AI eng, Fowler) over an investigate→debate→converge→re-audit cycle (unanimous converge-with-refinements; see design "Review round"). Grounded in RFC §1.2.1 (the governing principle) and App. **D.34**, generalizing **D.26/D.33**.

## What Changes

The governing principle (RFC §1.2.1, App. D.34): **Dusk's deterministic core may drive control flow only on signals it itself authored or that are universal across every stack** (its own timeout firing; whether returned bytes parse into Dusk's *own* schema). **Anything requiring judgment about what a specific tool's output means — the project's tech surface — must be interpreted by the agentic bridge, never hard-coded in the core.** Every boundary crossing resolves to **exactly one** of `content | no_verdict | transport`.

- **One classifier vocabulary + one three-way outcome, in the `core/schema` leaf (the root fix).** A flat `BoundaryOutcome = content | no_verdict | transport` discriminated union (a TS type — *not* a Zod schema; it is internal control flow, never persisted) and one classifier, in `@dusk/core-schema`, extending `modelCallError.ts`. One new error kind `infrastructure_no_verdict` (the `no_verdict` reason rides as a `detail`, not as N error kinds), one new bead status `paused_infrastructure`. The classifier is a **gate** every boundary routes through — not a vocabulary nine sites opt into.
- **Require positive success evidence — never infer a verdict from silence (the principle, mechanized).** The Verifier procedure SHALL replace `?? false` / `?? "vague"` with a **positive completeness check at both triple and support level**: every triple in scope must have a matching answer and every support a matching entry; any missing/degraded unit ⇒ `no_verdict` (incomplete), never a fabricated `fail` and never a false-converge. This subsumes the parseable-empty `{triples:[]}` degenerate (the live trigger).
- **A mechanical floor for Stage-2 that does not re-couple to a toolchain (decision ①).** Mirroring how the project's *code* is decorated to map to Dusk's *intent* schema, the project's *test command* emits results in **Dusk's own result schema** via a thin **project-side adapter/reporter** (the project's tech surface, configured in the foundation intent — a Phase-VI/project-side task, **not** part of this dusk change). The core reads only Dusk's own schema (`failed>0 ⇒ content fail`; `passed>0 ∧ failed==0 ⇒ pass`; non-run ≠ fail) and — checking its own liveness facts — treats a schema-absent / not-ran-to-completion / OOM-truncated result as `no_verdict`, never `pass`. The Test Runner core captures only `{command, exitCode, stdout, stderr, timedOut}`; flake-vs-failure judgment on schema-absent raw output is **agentic**, and the agent can only push toward `no_verdict`/`fail` — never downgrade a Dusk-schema assertion failure to a flake, never manufacture a green (the asymmetry guaranteeing the "no masked failure" dual).
- **Stop the silent green (the most dangerous gap — do first).** The orchestrator's Stage-2 path currently pushes the test intent as "executed" **without ever reading `TestVerdict.decision`** ([stateMachine.ts:349](../../../packages/runtime/orchestrator/src/stateMachine.ts#L349)). The Test Runner SHALL classify a content `decision:"fail"` as a `reenter_step4` outcome so the orchestrator routes it through the **existing** livelock-observation block ([stateMachine.ts:334-347](../../../packages/runtime/orchestrator/src/stateMachine.ts#L334-L347)) — re-draft + blocked commit, with zero new orchestrator branches (no new unbounded loop); and a `no_verdict` outcome to the infra axis.
- **Stop the downgrade (the latent twin).** The three sites that mint `recoverable:false` from an empty/degraded verdict ([loop.ts:172](../../../packages/runtime/short-cycle/src/loop.ts#L172), [run.ts:77](../../../packages/runtime/test-runner/src/run.ts#L77), [longCycle.ts:36](../../../packages/runtime/long-cycle/src/longCycle.ts#L36)) SHALL route empty/degraded → `infrastructure_no_verdict` on the recovery axis. Because nothing downstream consumes `recoverable` on these return paths, this requires a **new `no_verdict` outcome kind** on `ShortCycleOutcome` and `TestRunnerOutcome` (peers to `budget_exhausted`), routed like `budget_exhausted` routes to the ladder.
- **Guard every opaque-output boundary against a crash.** `execFileSync` → `spawnSync` in the Test Runner (non-zero exit is data, never a throw) at [vitest.ts:18-19](../../../packages/runtime/test-runner/src/vitest.ts#L18-L19) and the CLI runner ([implement.ts:434-444](../../../packages/cli/src/implement.ts#L434-L444)); every `JSON.parse` over opaque output guarded; a defensive `catch` arm on the orchestrator's `try…finally` ([stateMachine.ts:144,213](../../../packages/runtime/orchestrator/src/stateMachine.ts#L144)) so a sync throw in `processBead` surfaces a legible DuskError, never an `exit 1`.
- **A finite infrastructure-recovery axis (the new holes).** `no_verdict` surfaces on a **finite counter** with a terminal **legible, resumable pause** (`paused_infrastructure`): precedence `livelock > no_verdict > budget` in [precedence.ts](../../../packages/runtime/livelock-detection/src/precedence.ts); `no_verdict` iterations **excluded from livelock reject-observations** (infra noise must not trip the 3-consecutive-reject detector, and consecutiveness is over the *content* observation sequence); the pause reuses the existing freeze/`resumeFrozenBead` seam ([stateMachine.ts:401](../../../packages/runtime/orchestrator/src/stateMachine.ts#L401), CLI `bd_` dispatch [implement.ts:465](../../../packages/cli/src/implement.ts#L465), `BEAD_STATUSES` [activeRun.ts:14-25](../../../packages/runtime/orchestrator/src/activeRun.ts#L14-L25)); and a `no_verdict` long-cycle confirmation spawn is **neither a confirming reject nor a flaky-dismiss** ([longCycle.ts:62-102](../../../packages/runtime/long-cycle/src/longCycle.ts#L62-L102) preserved) — it routes the bead to the infra axis.
- **One vocabulary, not two.** The two ad-hoc retry checks in the CLI ([implement.ts:421,428](../../../packages/cli/src/implement.ts#L421-L428)) — which re-classify `verifier_model_call_failed` outside the core classifier — SHALL be folded into the single classifier (R2). The existing dead kind `test_runner_command_failed` is superseded by `infrastructure_no_verdict` for the Stage-2 boundary.
- **Out of scope, deliberately.** `git` `execFileSync` in `commit.ts`/`merge.ts`/`worktree.ts` is a **universal orchestration signal** (git exit codes are stable; it is Dusk's own orchestration substrate, not the project's tech surface) — kept outside the boundary-outcome union, an intentional, stated asymmetry. Gap #7 ([modelClient.ts:178](../../../packages/runtime/verifier/src/modelClient.ts#L178) unguarded success-path `JSON.parse`) is **already mitigated** at the spawn seam (a `SyntaxError` is classified transport via `modelCallError.ts:42` and surfaced) — it lands as a **guard regression test**, not a new fix (honest count: **eight fixes + one guard-test**, carried under the "nine-gap" lineage framing).

## Capabilities

### New Capabilities

- `boundary-outcome-handling`: Every model-call leg and opaque-tool-output boundary resolves to exactly one of `content | no_verdict | transport` via a single classifier in the `core/schema` leaf. The deterministic core acts only on signals it authored or that are universal; the agentic bridge interprets the tech surface and can only push toward `no_verdict`/`fail`. Both honesty duals hold **model-independently**: an infrastructure `no_verdict` never drives a futile loop, never crashes, never silent-greens, and is resumable; a genuine content `fail` still drives re-draft and still blocks commit. The mechanical guards (positive completeness check, the Dusk-result-schema floor, parse-into-Dusk-schema, the routing tables, the finite counters, consuming `decision`) are zero-model and regression-tested.

## Verifiability / acceptance

Success = an infrastructure `no_verdict` **never** drives a futile loop, never crashes, never silent-greens, and is resumable; a genuine content `fail` **still** drives re-draft / blocks commit; the mechanical guards hold **both duals model-independently**; the core stays tech-agnostic. Concretely (zero-model unless noted):

- **Dual A (no false loop):** a scripted verifier double returning empty/degraded/`{triples:[]}` → outcome is `no_verdict` (recovery axis), NOT a content reject; the short cycle does not re-draft and does not consume content-iteration budget.
- **Dual B (no masked failure):** `runTestRunner` yielding a Stage-2 `decision:"fail"` → bead re-enters Step 4 via the livelock-observation block; `commitBead` is NOT called; no green summary. AND a content `focal_verdict:"fail"` still drives re-draft (guard against over-broad `no_verdict` capture).
- **Completeness (the live trigger):** a degraded `{triples:[]}` under a non-empty triple set ⇒ `no_verdict`, never converge; a missing support entry ⇒ `no_verdict`, not a fabricated `vague`/`fail`.
- **Dusk-result-schema floor:** `failed>0 ⇒ fail`; `passed>0 ∧ failed==0 ∧ completed ⇒ pass`; `not_run`-only ⇒ `no_verdict`; schema absent ⇒ `no_verdict`; a `failed:0` with `completed:false` (OOM/SIGKILL-truncated) ⇒ `no_verdict`, never `pass`.
- **Crash guard:** `spawnSync` non-zero exit returns data (no throw); malformed JSON ⇒ `no_verdict`, not a thrown crash; a thrown `processBead` is caught and surfaced as a legible DuskError, never `exit 1`.
- **Finite axis + resume:** N consecutive `no_verdict` ⇒ terminal `paused_infrastructure`; precedence `livelock > no_verdict > budget`; infra iters excluded from livelock observations (the 3-reject detector does not fire on infra noise, and a real interleaved livelock still trips); `--resume bd_…` re-enters `processBead` from the frozen iteration.
- **Long-cycle honesty:** original `reject` + two `no_verdict` confirmations ⇒ does NOT dismiss as flaky and does NOT emit clean → routes to the infra axis.
- **Narrow/honest:** a `TypeError` on any boundary still propagates loud (never swallowed into `no_verdict`); the agentic bridge can never turn a Dusk-schema `fail` into `no_verdict`/`pass`.
- `openspec validate boundary-outcome-handling --strict` passes; `pnpm build`/`typecheck`/`test` green.
