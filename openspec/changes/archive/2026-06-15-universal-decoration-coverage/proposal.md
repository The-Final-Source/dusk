## Why

v9 asserts **total decoration**: every line of code links to the intents it serves, so any code is always traceable back to intents (RFC §4.1, §4.5). But the only decoration encoding is **inline `// @intent` comments**, which is impossible in **comment-less formats** — most importantly `package.json` (strict JSON cannot carry a comment). So total decoration was not actually total: a greenfield project built entirely through Dusk contains files that cannot be linked to intents at all, and nothing enforces their coverage (the gate's `isGatedFile` skips them). The greenfield POC (Phase 6) surfaced this directly — its `package.json`/config cannot be decorated, so the POC cannot honestly claim full intent↔code linkage.

A **decoration board (3 rounds)** designed the closure, recorded as **RFC App. D.28** (+ Ch. 4.5.4). This change implements it. It is a **standalone v1.x capability change** (not a plan phase) and a **prerequisite for a fully decoration-covered greenfield POC** — built before the POC restarts from scratch. The deviation from "one OpenSpec change per plan phase" is deliberate and board-ratified: this is a cross-cutting decoration capability surfaced by the POC, larger than a D11 support fix, warranting its own spec-driven change.

## What Changes

- **Keystone fix (lands first).** The existing directory `.intent` sidecar is parsed **only by the gate** (`checks.ts`) and is **invisible to the index-building scanners** — the three `.ts`-only walkers (`packages/delivery/mcp-server/src/context.ts` `scanDecorations`, `packages/cli/src/project.ts` `scanDecorations`, `packages/cli/src/doctorStaticAnalysis.ts` `collectSources`) never read it, so `.intent` records never reach `buildDerivedIndex` → invisible to the Verifier, reverse-index, and doctor. Collapse the triplicated walkers into **one shared `.intent`-aware scanner** in `@dusk/core-decoration`, with a test that fails today. This is the foundation everything else rides on.
- **Per-file sidecar encoding `<filename.ext>.intent`** (e.g. `package.json.intent`) — a third decoration parser feeding the same `DecorationRecord[]` (ONE model, not a second system). Reuses the already-gated `.intent` extension (zero `isGatedFile` change; auto-gated on both the live hook and the headless `gateWorktreeEdits`). Distinguished from the directory `.intent` by basename (exactly `.intent` → directory scope; a stem + `.intent` → per-file sidecar for `<stem>`). Body is JSON: `{ schema_version, target, claims:[{ anchor, marker, intent_path, aspect_ids? }], ignore:[{ anchor, because, reason }] }`.
- **Structural anchors stored; line view derived.** The stored source-of-truth is a **JSON Pointer** (RFC 6901) into the target (`/scripts/build`; `""` = whole file); line ranges are **never stored** — they are resolved every run by a location-aware JSON parser (pointer → AST node → line span). Drift-proof by construction: a dangling pointer is a **hard finding**, never a silent skip. No source-map machinery, no content hashes, no stored line numbers.
- **Universal full-coverage enforcement.** Every file **not** matched by the ignore set must be **fully covered** — comment-bearing files inline, comment-less files via the sidecar. Coverage is per-run set arithmetic: `uncovered = non-trivial-lines − covered − ignored` (blank/structural-only lines excluded). Any gap **hard-blocks at the gate** (full coverage always). Whole-file (`@intent-file` / root pointer) is the maximal tile and the floor for unstructured targets.
- **A dusk-level ignore mechanism — the ONLY exemption.** `dusk.config.yml` gains `decoration.ignore: [<globs>]` (built-in defaults `node_modules/**`, `.git/**`, `.ia/runtime/**`, `dist/**`, `build/**`, `coverage/**`, `**/*.lock`, `.env*`, merged with project additions) — the single source of truth consumed by the gate, the coverage scanner, and doctor (it **replaces the hardcoded `SKIP_DIRS`** in `doctorStaticAnalysis.ts`). Distinct from the per-claim `@intent-ignore` marker (a documented region *within* a covered file).
- **Comment-less records are verified mechanically/structurally**, never routed to the semantic Verifier (a manifest has no architectural triple to judge) — verified by anchor-resolution + the existing Stage-2 build/test, reported on the mechanical channel only (never blended into semantic adherence).
- **Scope: JSON-only sidecars** (whole-file fallback for any other comment-less format); not a general any-format region map (the named over-engineering trap).

## Capabilities

### New Capabilities

- `comment-less-decoration`: The per-file `<filename.ext>.intent` sidecar — its parser, the structural JSON-Pointer anchoring (stored source-of-truth), the derived line view (resolved every run, never stored), the JSON body schema, and the basename-based dispatch distinguishing it from the directory `.intent`. Normalizes to `DecorationRecord[]`; the greenfield foundation's `package.json` is its first real consumer.
- `decoration-coverage`: Universal full-coverage enforcement — the `decoration.ignore` glob SSoT (replacing the hardcoded skip set), the per-run coverage computation (`uncovered = non-trivial-lines − covered − ignored`), hard-block gate enforcement (full coverage always), and the doctor coverage report. The two-tier ignore model (project glob vs per-claim `@intent-ignore`).

### Modified Capabilities

- `decoration-parser`: **The keystone** — collapse the three `.ts`-only index walkers into one shared `.intent`-aware scanner so directory `.intent` AND per-file sidecar records reach `buildDerivedIndex` (today only the gate sees them).
- `pretooluse-gate`: New sidecar + coverage checks and rejection kinds (`uncovered_target_lines`, `unresolved_anchor`, `overlapping_anchors`, `malformed_sidecar`, `sidecar_target_missing`); consume `decoration.ignore`.
- `static-analysis-doctor`: Coverage reporting over comment-less files; consume the `decoration.ignore` SSoT in place of the hardcoded `SKIP_DIRS`.
- `verifier-procedure`: Structural/comment-less records are excluded from the semantic Verifier prompt and verified mechanically.

## Impact

- **Affected code:** `packages/core/decoration` (new sidecar parser + shared scanner + `DecorationRecord` `anchor` field + JSON-Pointer resolver), `packages/delivery/pre-tool-use` (gate checks + rejection kinds + ignore consumption), `packages/cli/src/{project.ts,doctorStaticAnalysis.ts}` + `packages/delivery/mcp-server/src/context.ts` (use the shared scanner), `packages/core/schema` (the sidecar body schema + `dusk.config` `decoration.ignore`), `packages/runtime/verifier` (structural-skip).
- **Determinism:** the sidecar parser, anchor resolution, coverage computation, and ignore matching are **zero-model** mechanical passes. Comment-less verification is mechanical (anchor resolves + Stage-2 build/test); the semantic Verifier is never asked to judge config.
- **Non-goals:** no general any-format region map (JSON-only sidecars; whole-file fallback otherwise); no source-map/VLQ machinery; no stored line numbers/content hashes; no change to inline decoration for comment-bearing code (D.11 stands — inline is mandatory where possible, sidecars forbidden on commentable files).

## Verifiability / acceptance

Success = the keystone test (a directory `.intent` / per-file sidecar record appears in `buildDerivedIndex` output and is visible to the Verifier/reverse-index/doctor — fails today, passes after); a `package.json.intent` sidecar with JSON-Pointer anchors yields correct **derived** line spans and full-coverage tiling; an uncovered non-trivial line in a non-ignored file **hard-blocks** at the gate; a dangling pointer is a hard `unresolved_anchor`; an ignored file/dir (per `decoration.ignore`) requires no coverage; comment-less records never enter the semantic Verifier prompt. All new mechanical passes are zero-model and unit-tested. **When this archives, total decoration is genuinely total — every non-ignored file in any format links to intents — and the greenfield POC can be built with full coverage.**
