## Why

Phases 1–4 built the complete v9 machine — constraint language, gate, runtime, Verifier, the 9-step pipeline, and the authoring dialog — but its load-bearing claims remain **assertions, not measurements**. The Engineer ⊥ Verifier asymmetry is structurally protected (P2-T1/T3, P3-T8) but never empirically audited; detection rates per violation class have never been measured against a ground-truth fixture; decoration erosion (`S ⊄ D`) has no off-write-path detector; the N=2 confirmation pass's underlying assumption (real-Verifier rejects on clean code are rare) has never been characterized against the real model; and Dusk has never run on real code — only fixtures. Without Phase 5, v1 cannot honestly claim its properties hold: the fresh-Verifier audit converts the asymmetry from assertion into measured property, the seeded-violations benchmark converts "the gate catches mechanical defects" into a per-class detection rate, and the dogfood converts "the pipeline works" into a mergeable commit on a real package with named go/no-go thresholds. **When this change archives, v1 is landed** — every row of the plan's commitment→phase coverage matrix is delivered.

This change delivers **exactly Phase 5 of the v9 implementation plan** (`docs/rfcs/001-mvp-rfc/v9-implementation-plan.md` lines 708–831), grounded in RFC §4.6, §7.2, §7.3, §7.4, §7.5, §7.5.1, §8.9, §2.1 (`conflicts` doctor behavior), App. A.6, App. A.8, App. B, and the roadmap Sprints 9–10.

## What Changes

- **`packages/runtime/observability` (complete)** — `SubAgentTrace` emission with **all v9 fields**: `schema_version`, `index_snapshot_id`, `iteration_number`, `verdict_delta_from_prior`, `failing_triple_set`, `engineer_change_summary`, `convergence_diagnosis_present` (Bead-Orchestrator only), `stuckness_detector_state`, `verifier_livelock_signal`, `confirmation_of_trace_id`, `confirmation_pass_outcome`, `skills_loaded[]`. Ring-buffered `traces.jsonl`. **Optional out-of-band PostHog/OTLP mirrors that never block or stall a pipeline run** — an unreachable sink produces no pipeline error (the mirrors are the one *unmanaged* dependency in v1's test surface).
- **`packages/runtime/benchmark`** — the per-role per-model harness (`/dusk-benchmark` + `dusk benchmark` CLI) producing per-model per-class accuracy, per-role-per-model latency/cost, and a cross-model Verifier-verdict agreement matrix; plus **`--audit-verifier-freshness`** implementing the **three-axis fresh-Verifier audit**:
  - **Axis 1** — verdict variance (Shannon entropy across N≥10 independent calls).
  - **Axis 2** — rationale similarity (token overlap).
  - **Axis 3** — **citation precision**: structural `file:line` parse of verdict rationales vs the fixture's `ground_truth_defect_loc`, three-tier `aligned` (±2 lines, same file) / `adjacent` (same-file-far or 1-hop import) / `unaligned` (wrong/absent) — **no LLM-judge anywhere in the audit**.
  - **Pre-registered thresholds (board round 4):** pass bars calibrated on a held-out controversial/known-good split and **frozen before the known-bad set is scored** — calibration data is never test data. All three axes carry explicit numeric bars (Axis 1/2 are not "vibes"). A Verifier producing no `file:line` citation is flagged (Axis 3 → all-`unaligned`), never silently degraded.
  - **Organic cohort:** confirmation-pass calls aggregate via `confirmation_of_trace_id` into a distinct cohort whose report carries an explicit selection-bias annotation (`selection: first-call-rejected`, `precision_not_comparable_to_curated`) — the no-blended-metrics rule enforced mechanically.
  - **Rubber-stamp detection:** the High-similarity × Low-precision quadrant per RFC §7.5.1's table, asserted against a deliberately rubber-stamping prompt variant.
- **`packages/runtime/benchmark` — flake-rate characterization (P5-T8)** — a high-N statistical characterization of first-call-reject → confirmation-outcome on clean fixtures against the real frontier model. **Non-gating**: the harness must produce the report with tolerance bands; no specific rate is asserted (the confirmation-pass *mechanism* was gated in P3-T14/T15 with the Verifier double).
- **`dusk doctor --static-analysis`** — the `S ⊆ D` decoration-erosion drift detector: call-graph + decorator lookup per decorated unit; **conservative default** (uninstrumented callees contribute empty intent sets — no false-positive floods); **`--strict-unknowns`** surfacing uninstrumented callees as a distinct `undecorated_callee` finding class; findings carry `file:line` + a suggested decomposition; framed as drift detection, not real-time enforcement.
- **`dusk doctor` conflicts-pair co-decoration flag (P5-T7)** — the second half of the `conflicts` typed-edge semantics: code carrying both `@intent A` and `@intent B` where A `conflicts` B is reported with `file:line` (the Decomposer's hard refusal covered bead-issue time; this covers the off-write-path surface).
- **`packages/fixtures/seeded-violations/`** — ~60 violations across **four classes**: mechanical (gate-caught, must be 100%), static-analysis (doctor-caught, not gate-caught), verification (Verifier-caught — including quantifier-cardinality, `implies`-consequent-on-antecedent-true, and negative-polarity-should-reject cases), and two-stage-test (caught by the Verifier's test-body evaluation, not the Test Runner). Every seeded-bad fixture YAML carries `ground_truth_outcome` + **`ground_truth_defect_loc: {file, line}`** (the citation-precision scorer's ground truth).
- **`packages/fixtures/worked-example/`** — the App. B `sendNotification` clean decoration as a **standing `dusk verify` regression fixture wired into the CI test surface** — every PR re-validates it.
- **Dogfooding (Sprint 10)** — author intents for + decorate `packages/shared` (pure leaf) under the gate; run `dusk_implement` for a small real feature request; run `/dusk-doctor` periodically; operate ≥2 weeks; **hard go/no-go thresholds**: ≥1 successful end-to-end `dusk_implement` producing a mergeable commit with full trailers AND `packages/shared`'s existing test suite stays green AND gate false-positive rate = 0 on the decorated package AND the worked-example regression stays clean. Iteration-distribution and Author-branching metrics are recorded as **exploratory, explicitly non-gating**. Expansion toward `packages/api` begins within the window.
- **Ecosystem skeletons** — registry canonical-intent search/download routes in the **existing** `packages/api` (new routers/services per the repo's platform-distribution note) + adherence / intent-tree / decoration-coverage views in the **existing** `packages/web`. Routable/renderable, not feature-complete. **This is the only phase that touches the app packages.**
