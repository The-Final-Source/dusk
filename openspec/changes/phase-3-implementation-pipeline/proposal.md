## Why

Phase 2 shipped the substrate that can spawn sub-agents and **verify** decorated code, but Dusk cannot yet produce code. Without Phase 3, an operator has no way to turn an intent set into commits on `main`: the 9-step `dusk_implement` pipeline — request decomposition, bead DAG with overlap detection, worktrees, short cycle, long cycle, test execution, atomic commits, topological merge, return summary — does not exist. Phase 3 is also the only place where Phase 2's load-bearing seams (`spawnSubAgent({verifierFactory?})`, the scripted-verdict double + `spawnCount`, the `Verdict` shape, the structured bead memory + `compact()`, the `raw_prompt` no-leak invariant) are *exercised in a real orchestration loop*. Phase 4 (Author dialog) plugs into the pause/resume contract pinned here; Phase 5 (validation + dogfooding) measures what Phase 3 produces.

This change delivers **exactly Phase 3 of the v9 implementation plan** (`docs/rfcs/001-mvp-rfc/v9-implementation-plan.md` lines 383–600), grounded in RFC §2.10, §3.4, §3.4.1, §6.2–§6.9, §6.4.1, §6.4.2, §6.5, §8.9, §10.1, §10.1.1, §10.1.2, §10.2, App. A.5, App. A.7, App. A.11, App. D.3.

## What Changes

- **Session-snapshot index** built once at pipeline entry from the merge-base, hashed onto every trace as `index_snapshot_id`, immutable for the run; per-bead **in-memory delta** visible only to that bead; cross-bead queries see the snapshot only; `--rebuild-index` forces a new snapshot within the same session.
- **Step 1 Decomposer** — typed `relates_to` walking (`implies`→auto-add, `conflicts`→`decomposer_bead_conflict` hard refusal, `supersedes`→exclude target, `parent`/path→scope+edge, `sibling`→context-only no auto-expand); test-pyramid children auto-added; unresolved-intent emits `implement_paused_for_authoring` with a disk checkpoint.
- **Step 2 Bead DAG** — typed-dependency edges + **file-overlap serialization edges** + **cross-bead claim-overlap precondition**: focal-claim overlap → HARD `decomposer_bead_conflict`; support-claim overlap → advisory warning surfaced in run summary.
- **Step 3 Worktrees** — parallel beads get isolated `dusk/<bead-id>` worktrees off the snapshot's merge-base; orphan reaping via `dusk doctor --cleanup-worktrees`.
- **Step 4 Short cycle** — Engineer ↔ fresh-per-call Verifier loop; **stuckness detector** (3-iter window over `verdict_delta_from_prior` + stable `failing_triple_set` → diagnosis fires as early as iter 3); **iter-5 forced-diagnosis fallback** when stuckness hasn't fired; **iter-15 early escalation** with the bead-memory diagnosis as payload; **per-entry ceiling + 40-iter bead lifetime budget** (relationship, not literals — both config-driven); gate-fail loopback (no Verifier call on blocked drafts); `focal_verdict: fail` loopback; `support_quality: low_confidence` does NOT trigger re-draft (the verdict-split loop consequence).
- **Step 4 Recovery Ladder — all four levels (NEW per board round 4: full ladder now lands in Phase 3, not split to Phase 5)** — L1 partial commit (`Partial: true` + `Deferred-Intent` trailers + `deferred.yaml`); L2 intent-modification proposal aggregating ALL lifetime diagnoses → `intent-proposal.yaml` + `DuskError{kind:"bead_intent_revision_needed", recoverable:true}`; L3 operator-actionable freeze → `freeze-state.md` + worktree preserved + `DuskError{kind:"bead_frozen", recoverable:false}` + `dusk implement --resume`; L4 hard abort fires ONLY when L3 freeze cannot serialize. L2's *recovery action* (`dusk_author_continue`) lands in Phase 4; L2's *artifact + error contract* ships here.
- **Step 5 Long cycle** — affected universe = direct ∪ adjacent (1-hop), snapshot-only (bead-local delta excluded); **N=10 shuffle sharding**; **N=2 confirmation pass on first reject** (`confirmation_of_trace_id`; ≥1/2 confirm → `confirmed_reject` + re-enter Step 4; both override → `flaky_verdict_dismissed` + continue).
- **Step 6 Test execution + livelock** — Test Runner role; **two-stage satisfaction** (Verifier pre-pass on test bodies before any execution; only Verifier-validated tests reach the Vitest run); per-test-intent `TestVerdict` (App. A.5); **Test-Verifier livelock detector** (same `(test_intent, triple)` rejected ≥3 iters + slot-focus ≥80% + ≥3 distinct taxonomy approaches) → `TestVerifierLivelockReport`; `dusk_resolve_livelock({bead_id, verb})` with the three verbs `accept_test_as_is` / `modify_triple` / `escalate`.
- **Step 7 Atomic commit** — Conventional Commits + the full v9 trailer set (`Intent`, `Test-Intent`, `Bead-id`, `Verdict-id`, `Trace-id`, `Test-Verdict-id`, `Verifier-model`, `Test-Runner-model`, `Long-cycle-samples`, `Test-Suites-passed`; conditional: `Partial`, `Deferred-Intent`, `Verifier-bypassed-test-intent`). One commit per bead.
- **Step 8 Worktree merge** — topological rebase per the DAG; recognize `Partial: true` so deferred-intent additions don't trigger `snapshot_drift`; **decorator-aware Conflict Resolver** prefers more-specific decorations and surfaces equal-specificity ties as TODOs.
- **Step 9 Return summary** — `{commits[], beads_summary[], intents_touched[], test_intents_executed[], trace_ids[], total_duration_ms, total_cost_usd}`.
- **Pause/resume** — disk checkpoint at `.ia/runtime/implement/<resume_token>.json` with the **frozen RFC §10.1.1 field set** — `{original_request, scope_hint, decomposer_partial_state, intents_resolved_so_far, intents_still_unresolved, suggested_dialog_seed, unresolved_refs, created_at, last_touched_at}`. **The checkpoint JSON shape is the frozen cross-proposal interface (NEW per board round 4)**: Phase 4 *consumes* this file; Phase 3 ships `suggested_dialog_seed` present-but-naive (raw unresolved-ref list); Phase 4 enriches its *content* without changing its *shape*. `dusk_implement({resume_token})` overload; single-use checkpoint (deleted on Step-1 transition); 24h TTL with `dusk doctor --gc-implement-checkpoints`; `implement_resume_token_expired` preserves `original_request` in `recovery_hint`.
- **Cooperative cancel** — `dusk_cancel({bead_id?, reason})` → `CancelResult`. Flag-and-drain semantics (Claude Code Task has no abort primitive); ordered cleanup (dialogs → checkpoints → bead memory → worktrees with no commits); `partial_commits[]` preserves bead branches with commits for user decision; `already_committed` preserved; emits `cancellation_already_committed` informational on already-merged targets.
- **CLI + MCP** — `dusk_implement({request? | resume_token?, scope_hint?})`, `dusk_cancel`, `dusk_resolve_livelock`, `/dusk-test` slash command; `dusk implement` + `dusk implement --resume <bead-id>` CLI mirrors; new `dusk doctor` subcommands: `--cleanup-worktrees`, `--gc-implement-checkpoints`, `--gc-dialogs`.

## Capabilities

### New Capabilities

- `session-snapshot-index`: Pipeline-entry frozen snapshot of the derived-index query interface + per-bead in-memory delta with bead-local visibility; `index_snapshot_id` on every trace; `--rebuild-index`.
- `bead-decomposition`: Step 1 Decomposer (typed-`relates_to` walking, test-pyramid auto-add, unresolved-intent pause) + Step 2 Bead DAG (typed-dependency + file-overlap + cross-bead focal/support overlap; focal=hard refusal, support=warning).
- `worktree-orchestration`: Step 3 parallel/serial decision + `git worktree add -b dusk/<bead-id>`; `dusk doctor --cleanup-worktrees` orphan reaping.
- `short-cycle`: Step 4 Engineer ↔ fresh Verifier loop + stuckness detector + iter-5 fallback + iter-15 escalation + per-entry ceiling + 40-iter lifetime budget; verdict-split loop consequence (`support_quality: low_confidence` is non-blocking).
- `recovery-ladder`: All four levels (L1 partial commit; L2 intent-modification proposal; L3 freeze + resume; L4 abort), the deterministic cascade based on satisfaction state at exhaustion + freeze-serializability.
- `long-cycle`: Step 5 affected-universe (direct ∪ adjacent, snapshot-only) + N=10 shuffle sharding + N=2 confirmation pass on first reject.
- `test-execution`: Step 6 Test Runner role + two-stage satisfaction (Verifier pre-pass) + Vitest invocation + per-test-intent `TestVerdict` (App. A.5); configurable suffix discovery.
- `livelock-detection`: Test-Verifier livelock 3-condition detector + `TestVerifierLivelockReport` + `dusk_resolve_livelock` MCP tool (three verbs).
- `commit-merge`: Step 7 atomic commit with the full trailer set + Step 8 topological rebase + decorator-aware Conflict Resolver + Step 9 return summary.
- `implement-checkpoint`: Disk-resident pause/resume with the frozen §10.1.1 JSON shape; 24h TTL; single-use; `dusk doctor --gc-implement-checkpoints`.
- `cooperative-cancel`: `dusk_cancel` flag-and-drain semantics + `CancelResult` + ordered cleanup + cancelled/preserved partitioning.
- `implement-write-surface`: `dusk_implement` MCP tool wiring the 9-step state machine (incl. `resume_token` overload) + `dusk implement` / `dusk implement --resume` CLI mirrors + `/dusk-test` standalone Test Runner.

### Modified Capabilities

- `mcp-read-surface`: `dusk://beads/active` + `dusk://implement-checkpoints` (+ paired `dusk_list_beads`, `dusk_list_implement_checkpoints`) now serve real populated collections; `dusk_inspect` continues to expose `low_confidence_supports[]` populated from in-run verdicts.
- `dusk-cli-substrate`: New commands `dusk implement` (request/resume), `dusk doctor --cleanup-worktrees`, `dusk doctor --gc-implement-checkpoints`, `dusk doctor --gc-dialogs`, plus the `/dusk-test` slash command, each with working `--help`.

## Impact

- **New packages:** `packages/runtime/{decomposer, worktree, short-cycle, recovery-ladder, long-cycle, test-runner, livelock-detection, commit, merge, conflict-resolver, implement-checkpoint, cancel}`; orchestrator gains the session-snapshot index + Bead Orchestrator + the Step-by-step state machine.
- **Bound to Phase-1 + Phase-2 seams (no changes):** schema types, decoration record, derived-index query interface (Phase 3 swaps the backing to snapshot+delta per the Phase-1 design D6 contract — signatures unchanged), `Rejection`/hook contract, `dusk.config.yml` shape, test harness (temp-repo factory + injectable `Clock`); `SubAgentTrace` + `Verdict` + `VerifierFactory` + `VerifierFixtureScript` + `spawnSubAgent({verifierFactory?})` + bead memory format + `compact()` + `ModelClient` + `DuskError` envelope + `dusk_inspect` shape.
- **App packages (api/web/shared/hooks/mobile):** untouched (Phase-5 dogfood targets).
- **Determinism posture:** control-flow tests (stuckness, iter-5 fallback, iter-15 escalation, recovery ladder L1–L4, confirmation-pass mechanism, livelock detection, cancel drain, gate-fail loopback) run **zero-model** against the Phase-2 scripted-verdict Verifier double; verdict-correctness tests + the smoke matrix's primary path run against the **real frontier model** at `temperature: 0` with the pre-registered `N=3, threshold ≥2/3` protocol. P3-T8 carries an integration leg that derives `failing_triple_set` from real (temp-0) Verifier verdicts on a genuinely-stalling fixture to prove the upstream derivation is wired, not just the detector predicate.
- **Non-goals:** Phase 4 (Author 5-stage dialog, Stage 4.5 validations, dialog persistence, the L2 *recovery action* `dusk_author_continue` flow); Phase 5 (fresh-Verifier audit, `/dusk-doctor --static-analysis`, observability sinks, benchmark harness, seeded-violations fixture, dogfooding on a real package).
