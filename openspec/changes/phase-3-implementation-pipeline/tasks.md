> Ordered by dependency. The session snapshot is foundational (every later task reads through it); `implement-checkpoint` + `worktree-orchestration` are independent infra; `bead-decomposition` binds the first three; `short-cycle` + `recovery-ladder` are the loop heart; `long-cycle` + `test-execution` + `livelock-detection` are Steps 5–6; `commit-merge` is Steps 7–9; `cooperative-cancel` is orthogonal but touches all of the above; `implement-write-surface` wires everything via MCP; CLI mirrors land last; smoke + cohesive landing gates archival.
>
> Each task names its acceptance (capability spec scenario + plan slug P3-T*) and its Vitest test plan with explicit **determinism surface**. **Control-flow tasks** (snapshot coherence, gate-fail loopback, stuckness detector, iter-5/15, recovery ladder L1–L4, confirmation-pass mechanism, livelock detection mechanics, cancel drain, MCP envelope, etc.) run **zero-model** against the Phase-2 scripted-verdict Verifier double. **Verdict-correctness tasks** (stuckness derivation on a real stalling fixture, two-stage test satisfaction, smoke primary path) run against the **real frontier model at `temperature: 0`** with the pre-registered protocol `N=3, threshold ≥2/3`. **Unit-only** is reserved for pure transforms with no I/O. Scaffolding/wiring is unmarked.
