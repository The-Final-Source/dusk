## Why

v1 (Phases 1–5) built and measured the complete v9 machine, but it only ever ran on its *un*-native terrain. v9 is **greenfield-first by design** (RFC §8.2): decoration happens at authorship, code is born decorated, and the whole apparatus — total decoration, the gate, per-aspect verification — is cheapest and highest-fidelity when every line is born that way. Legacy bootstrap is deferred *precisely because* retro-decoration is the inverse mode (RFC §8.2, App. D.23). Yet the v1 dogfood (P5-T11) was brownfield-lite: it decorated *existing* code on a *pure-leaf* package (`packages/shared` — no DB, no HTTP, unit-only pyramid). Three gaps survive v1: **(a)** the thesis itself (RFC §1 — "humans express intents; the harness produces adherent code") has never run with **zero hand-written application code**; **(b)** the full test pyramid has never executed against **real infrastructure** (live Postgres, real HTTP) on real, non-fixture code — `packages/shared` has neither; **(c)** greenfield intent-tree authoring at application scale — Stage-2 tension detection as a tree grows from nothing — has only ever been exercised one intent at a time (P4-T1). This change closes all three in one artifact: a small, working API that exists only because Dusk built it.

This change delivers **exactly Phase 6 of the v9 implementation plan** (`docs/rfcs/001-mvp-rfc/v9-implementation-plan.md` lines 839–923; roadmap Post-v1 Sprint 11, line 939), grounded in RFC §1, §3.1/§3.1.1 (polarity), §3.2.1 (the `implies` operator's closed-vocabulary antecedents), §3.4 + §6.6 (the test pyramid + the Test Runner), §4.1 + §8.9 (total decoration + static analysis), §5 (the 5-stage authoring flow), §6.2 (file-overlap bead serialization), §6.7 + App. A.7 (commit trailers), §8.2 + App. D.23 (greenfield is native), and §10.1.1 (pause/resume). **Phase 6 is post-v1 and adds no rows to the commitment→phase coverage matrix** — it consumes the finished v1 runtime and reshapes nothing.

## What Changes

- **A fresh, standalone POC repository (the deliverable, built outside this monorepo).** A minimal **notifications API** on Dusk's own stack (TS strict ESM, Express + tRPC, Drizzle + Postgres, Vitest) — deliberately the canonical-intents / App. B `sendNotification` domain so the Author's Stage-2/Stage-3 machinery operates on familiar ground. 4–6 endpoints across ~2 resources: a **cursor-paginated list** (under the pagination intents), an **idempotent write** (under a `compose: implies` idempotency-on-writes intent with a closed-vocabulary antecedent), **structured-logging + error-handling cross-cutting intents**, and a **full pyramid** with integration-tests (real Postgres) + e2e-tests (real HTTP) children. Its git history is purely Dusk-authored and independently auditable. **No new dusk-monorepo package.**
- **The thesis constraint, mechanically audited: zero hand-written application code.** All application source — including every test body under the pyramid suffixes — is produced through the **CLI `dusk implement` path** (which wires the post-hoc `gateWorktreeEdits` gate over the worktree diff; the MCP write surface is gated-by-contract only and constructs no live file-writing engine, so it would run the short cycle ungated). Human inputs are whitelisted: authoring-dialog responses (`dusk_author_continue`), `dusk_implement` requests, `dusk_resolve_livelock` / recovery-ladder resolutions, and commit review/merge approval. **Nothing else.**
- **A trailer-audit script + transcript/provenance checker** (zero-model pure passes over the POC's `git log` + trace stream). The auditor verifies every commit touching **application source** carries the full v9 trailer set (actual keys per `packages/runtime/commit/src/render.ts`: `Intent`, `Test-Intent`, `Bead-id`, `Verdict-id`, `Test-Verdict-id`, `Trace-id`, `Verifier-model`, + the gated-path conditionals `Partial`/`Deferred-Intent`/`Verifier-bypassed-test-intent`) or is a merge of such commits, and that the whitelist covers every recorded human action. The **"application source" predicate is ruled explicitly** (see design.md): *required* = all runtime source + all test bodies under the pyramid suffixes; *exempt scaffold* (enumerated, minimal) = `dusk init` output, `package.json`/`tsconfig`/`vitest.config`/Drizzle config, generated migrations, and the Vitest `globalSetup` infra-provisioning + e2e app-boot helper. The auditor is **verified against the real `git log` of an actual pipeline run**, never a synthesized commit fixture (the load-bearing P0-gate lesson: mechanical-boundary checks must drive the exact production artifact).
- **`PocReport`** — a **new sibling schema in `@dusk/core-schema`** modeled on `DogfoodReport`'s two-section gating/exploratory *pattern* (NOT a literal reuse: `DogfoodReport`'s gating section is `.strict()`-locked to its own four dogfood thresholds; the POC's hard gates differ and are more). A `.strict()` **gating** section — zero hand-written code, all endpoints pipeline-landed, full pyramid green on live infra, gate false-positive rate = 0, tree 100% dialog-authored, static analysis clean in both modes — structurally separated from a `gating: false` **exploratory** section (dialog turn counts, Stage-3 acceptance rate, iteration distributions, pause/resume frequency, intent-granularity stats, time-to-endpoint). Its evaluator is a zero-model pure pass. Tooling lives under `packages/runtime/benchmark` (extension); the schema lives in `@dusk/core-schema`.
- **Measurement carry-over + friction feedback.** The Phase-5 instruments run against the POC (complete trace streams; periodic `dusk doctor` + `--static-analysis`); born-decorated code must show **zero erosion**. Greenfield-friction findings feed back into dusk role prompts/skills as ordinary reviewed commits in this repo.

## Capabilities

### New Capabilities

- `greenfield-poc-build`: The standalone POC repo built from `git init` + `dusk init` — Dusk operating against an external working directory; the ~10–20-intent tree authored entirely through `dusk_author` dialogs (≥1 `polarity: negative` triple, ≥1 closed-vocabulary `compose: implies`, pyramid children at unit + integration + e2e); the 4–6 endpoints built via the CLI `dusk implement` path (≥1 multi-bead/file-overlap run, ≥1 natural pause→author→resume); the full pyramid executing against live Postgres + real HTTP; the booted app's endpoints honoring cursor-pagination + idempotency semantics. (P6-T2..T7.)
- `zero-handwritten-audit`: The trailer-audit script + transcript/provenance checker — zero-model pure passes proving every application-source commit carries the full v9 trailer set (or is a merge of such), the human-input whitelist covers every recorded action, every intent traces to an author-role trace event + finalize `intents_created` record, and born-decorated code shows zero erosion under `dusk doctor --static-analysis` (both modes). The "application source" predicate is enumerated; the auditor is verified against a real pipeline `git log`. (P6-T1, T2 provenance, T8.)
- `poc-report`: The `PocReport` sibling schema in `@dusk/core-schema` + its zero-model evaluator — a `.strict()` gating section (the POC's hard gates) structurally separated from a `gating: false` exploratory section (greenfield-friction data seeding the v1.x backlog), modeled on `DogfoodReport`'s pattern without reusing its threshold-locked shape.

### Modified Capabilities

The greenfield/external-repo load surfaced three tightly-scoped robustness fixes that change v1 spec-level behavior — handled as D11 support work with living-spec deltas (the design's §6.5 / D11 policy), distinct from this change's deliverable scope:

- `author-five-stage-flow`: **ADDED** — Stage-2 tension detection gains a general fifth class, `prerequisite` (the request depends on an intent not yet in the tree). The runtime supplies a general `intent_census`; the Author surfaces a `prerequisite` tension (the greenfield foundation being its canonical instance) and steers authoring the dependency first. A surfaced tension flows through the existing transition — no bootstrap state in the orchestration, no pipeline special-case. (RFC App. D.24/D.25.)
- `worktree-orchestration`: **MODIFIED** — worktree creation uses the session snapshot's resolved merge-base SHA and **requires** an explicit `baseRef` (fail-loud), with no hardcoded `origin/main` default (absent in a standalone repo). (RFC App. D.27.)
- `session-snapshot-index`: **MODIFIED** — the default base ref resolves through `origin/main → main → HEAD`; an explicit `--base-ref` stays strict. (RFC App. D.27.)

One additional implementation-level correction happens as a task, **not** a spec delta: surfacing the existing `dusk implement --scope`/`--base-ref` flags in `dusk implement --help` — a bug fix against the existing `dusk-cli-substrate` requirement ("`dusk implement --help` … prints … a flag list"), not a new requirement. (The Engineer salvage-on-overrun fix, App. D.26, is implementation robustness against the existing `short-cycle` iteration contract — it changes no requirement, so no delta.)

## Impact

- **New standalone repo (outside the monorepo):** the POC application + its intent tree + its full pyramid. Its only non-pipeline commit is the initial `dusk init` scaffold (config/infra, not application source — documented so the auditor's predicate is unambiguous).
- **dusk-repo additions:** `PocReport` in `packages/core/schema`; the trailer auditor + transcript checker + `PocReport` evaluator under `packages/runtime/benchmark` (extension); friction-driven role-prompt/skill edits as reviewed commits; the one-line `dusk implement --help` flag fix.
- **Bound to ALL v1 seams (no reshaping):** the gate (`gateWorktreeEdits` + `isGatedFile`, external-repo-safe via `$CLAUDE_PROJECT_DIR`), the 9-step pipeline, `dusk_author`'s 5 stages + `DialogState`, the Verifier, the test pyramid + Test Runner (vitest-only — it provisions nothing; live infra comes from the POC's own `globalSetup`), `CommitTrailers`, the pause/resume `ImplementCheckpoint`, the livelock/recovery surfaces, the static-analysis detector, and the observability trace stream. Phase 6 adds **no runtime capability** and pins **no new cross-proposal seam** (it is terminal for this line of work).
- **Determinism posture:** the trailer auditor, transcript checker, and `PocReport` evaluator are **zero-model** pure passes; the **build itself** runs the production pipeline against the **real frontier model** (ambient Claude Code CLI, no API key, `temperature: 0`, the Phase-4 pre-registered transport-failure amendment applied) against **real git, real Postgres, real HTTP, real Vitest**.
- **Non-goals:** no legacy bootstrap (greenfield needs none — the entire point); no deferred v1.x feature (semantic/vector search, runtime canonical-library fetch, noun-phrase expansion, heterogeneous per-role models, hard sandboxing, etc. — Phase 6 requires none; wanting one means off-scope); no reshaping of any v1 runtime capability; no feature-complete product (4–6 endpoints, not forty).

## Verifiability / acceptance

Success = **every behavioral test P6-T1..P6-T8 passes** — the trailer auditor, transcript checker, and `PocReport` evaluator are zero-model pure passes; the build itself runs the production pipeline (real frontier model, ambient CLI, transport amendment applied) against real git/Postgres/HTTP/Vitest. The **phase-landing smoke test** is the scenario "from `git init` to a working API, hands off the code": `dusk init` → author the tree through real dialogs (incl. the polarity-negative, `implies`, and pyramid constructs) → a series of `dusk_implement` requests builds the app (≥1 multi-bead/file-overlap run, ≥1 natural pause→author→resume) → the app boots and its full pyramid (unit + integration vs live Postgres + e2e vs real HTTP) is green → the trailer audit confirms zero hand-written application code → `dusk doctor --static-analysis` is clean in both modes → the `PocReport` gates pass. The **cohesive-landing checklist** (plan lines 915–923) is the archival gate: all P6 tests green; the smoke scenario green end-to-end; the hard gates true; exploratory data recorded as non-gating in the `PocReport`; friction fed back into dusk role prompts/skills as reviewed commits; the POC repo publishable as the canonical greenfield reference. **When this change archives, v1.x has its first milestone landed.**
